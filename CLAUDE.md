   ссылки `?key=…` и `/…/access?next=…` просто приводят на страницу
   (`lib/showcase/access.ts`, `proxy.ts`). С 29.09.2026 все проекты витрины
   открыты и поисковикам (решение владельца: «мы не будем конкурировать»).
   Новый проект: в метаданных его layout — `robots: projectRobots`, и строка
   в `SHOWCASE_PAGES` (оба — `lib/showcase/seo.ts`), чтобы он попал в карту
   сайта. `noindex` на проекты не ставить; закрыты только `/admin` и API.
   Без `SHOWCASE_ROOT` (боевой сайт из этого же кода) чужие проекты
   по-прежнему закрыты — это делает сам `projectRobots`.
2. **Цены студии на витрине — только по коду.** Решение владельца от
   29.09.2026: код дают бот студии и менеджер (скаут), с ним док
   конструктора показывает цену каждого тумблера и итог. Без кода денег нет
   нигде — ни на странице, ни в разметке, ни в бандле. Прайс живёт только на
   сервере, в `lib/configurator/prices.ts` (`server-only`); браузеру его
   отдаёт `app/api/showcase/prices` после проверки кода. Сам код — только в
   `SHOWCASE_PRICE_CODE` в `.env.local` на сервере, в репозиторий его не
   класть (он публичный); пусто — цены закрыты для всех. Флагов, которые
   показывали бы цены без кода, не заводить. Цены внутри демо-контента
   заказчиков (квартиры, товары) — часть макета, их не трогаем.

# Макеты — под защитой

Решение владельца, 03.10.2026: правило обязательное для всех макетов витрины —
сделанных и будущих.

- **Строка с условиями** — `<MockupTerms />` (`components/showcase/mockup-terms.tsx`)
  в конце `<body>` каждого проекта: «Макет принадлежит DevUz Studio.
  Использовать его можно только по договору — условия использования», ссылка
  на `devuz.studio/{язык}/mockup-terms`. Показывается только на площадке
  (`SHOWCASE_ROOT=true`); на сайте заказчика из этой же сборки её нет.
- **Оттенки площадки** — `lib/showcase/tone.mjs`, второй шаг в
  `postcss.config.mjs`: каждый цвет, заданный переменной, при сборке
  сдвигается на 1–3 единицы, свой сдвиг на каждую переменную. Глазу не
  видно, а копия страницы уносит эти значения, и панель devuz.studio
  («Прототипы» → «Проверить сайт») узнаёт по ним витрину. Новый проект
  попадает под это сам, если его цвета заданы переменными (`@theme`,
  `[data-world]`) — так их и задавать. Сдвинутые значения не «исправлять».
- **Проверка** — `scripts/check-mockup-terms.mjs` перед `next build`: проект
  без `<MockupTerms />` или выключенные оттенки — сборка не идёт.

# Слияние PR — без вопросов

Решение владельца, 02.10.2026: «Сливай на автомате всегда, не спрашивай».
Свой PR сливается сразу, как только он готов: где есть CI — после зелёных
проверок, здесь CI нет — после своих `tsc`, `eslint` и `npm run build`.
Отдельного «можно сливать?» не спрашивать. Площадка подтягивает ветку сама
(`deploy/globalex-autodeploy.timer`, раз в минуту).
