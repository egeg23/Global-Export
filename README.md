# Global Export Company — корпоративный сайт

Новый сайт для узбекского производителя и экспортёра сельхозпродукции
[Global Export Company](https://www.globalex.uz) — замена текущему сайту на Wix.

Каталог, новости, страницы компании и заявки на трёх языках (EN / RU / UZ),
статическая генерация, реальный контент и фотографии перенесены с их
действующего сайта. Плюс админка на `/admin`: владелец сам добавляет новости,
товары, сертификаты и фотографии, без разработчика.

---

## Быстрый старт

```bash
npm install
cp .env.example .env.local   # можно оставить пустым для локального запуска
npm run dev                  # http://localhost:3000
```

Сборка и локальный прод-запуск:

```bash
npm run build
npm start
```

## Стек

| Слой | Решение | Почему |
|---|---|---|
| Фреймворк | Next.js 16, App Router | Статическая генерация всех страниц, встроенный `next/image`, SEO-метаданные из коробки |
| Стили | Tailwind CSS v4 | Токены темы прямо в CSS (`app/globals.css`), нет отдельного конфига |
| Языки | Свой лёгкий i18n (`lib/i18n.ts`) | Три языка без внешней библиотеки и без рантайм-оверхеда |
| Анимации | CSS-переходы + IntersectionObserver | Плавные появления при скролле без анимационных библиотек в бандле |
| Контент | Supabase (Postgres + Storage) с фолбэком на модули в `content/` | Владелец правит сайт сам; без базы сайт всё равно собирается |
| Админка | Server Actions + Supabase Auth | Никакого отдельного бэкенда и никакой CMS-подписки |
| Формы | Route Handler `app/api/lead/route.ts` | Отправка заявок в Telegram и (опционально) в Bitrix24 |

Во фронтенде четыре зависимости: `next`, `react`, `react-dom` и клиент
Supabase. Анимации, i18n, формы и работа с изображениями — свои.

## Админка

По адресу `/admin` — панель, из которой владелец сайта правит содержимое сам.
Разделы: **новости**, **продукция**, **категории**, **сертификаты**,
**команда**, **медиа**.

Что она умеет:

- **Три языка в одном поле.** У каждого текста переключатель EN / RU / UZ;
  точка на вкладке показывает, где перевод уже есть. Незаполненный язык — не
  ошибка: страница подставит первый непустой, то есть запись, добавленная
  только по-русски, покажется на всех языках по-русски, а не пустотой.
- **Фотографии перетаскиванием.** Файл кидается в область загрузки (или
  выбирается кликом — то же самое доступно с клавиатуры), уходит прямо в
  хранилище и сразу доступен во всех разделах через «Выбрать из медиатеки».
  JPG, PNG, WebP, AVIF и PDF до 10 МБ.
- **Черновики.** Запись без галочки «Опубликовать» видна только в панели.
- **Адреса страниц** составляются из заголовка автоматически, кириллица
  транслитерируется (`Экспорт в Нидерланды` → `eksport-v-niderlandy`). Поле
  остаётся редактируемым: у опубликованной страницы адрес лучше не менять.
- **Порядок** в каталоге, категориях, сертификатах и команде задаётся числом.

Изменения появляются на сайте сразу: после сохранения затронутые страницы
перегенерируются, отдельной публикации не требуется.

### Подключение базы

1. Создать проект в [Supabase](https://supabase.com) (бесплатного тарифа
   хватает) и применить миграции из `supabase/migrations/` — через
   `supabase db push` или скопировав SQL в редактор запросов.
2. Прописать в `.env.local` `NEXT_PUBLIC_SUPABASE_URL` и
   `NEXT_PUBLIC_SUPABASE_ANON_KEY` (Project settings → API).
3. Завести пользователя в Supabase Auth и добавить его в таблицу `admins` —
   только записи из неё дают право на изменения:

   ```sql
   insert into public.admins (user_id, email)
   select id, email from auth.users where email = 'admin@example.com';
   ```

4. Перенести содержимое из `content/` в базу:

   ```bash
   SUPABASE_URL=... SUPABASE_KEY=... \
     SEED_EMAIL=... SEED_PASSWORD=... node scripts/seed.mjs
   ```

Скрипт заходит под тем же паролем, что и панель, и пишет через те же политики
доступа — то есть заодно проверяет, что права настроены верно.

### Как устроен доступ

Ключ в браузере — публичный (`anon`), и этого достаточно, потому что права
раздаёт сама база:

- аноним читает только опубликованные записи и не может ничего изменить;
- изменять может лишь пользователь из таблицы `admins`; регистрация на сайте
  прав не даёт;
- черновики видны только администратору;
- сервисный ключ не используется нигде — ни в коде, ни в переменных окружения.

Страницы `/admin` закрыты проверкой на сервере и помечены `noindex`.

## Демонстрация анимации

`public/motion.html` — отдельная страница-проба по адресу `/motion.html`:
сухофрукты выходят в кадр, к ним подхватываются орехи, всё раскладывается по
трём корзинам. Сделана в ответ на вопрос клиента про анимации уровня
loeschs.de и отвечает на него по существу: сцена собрана из `position: sticky`,
`transform`, `opacity` и полусотни строк без единой зависимости.

Летящие объекты вырезаны из фотографий самой компании (`public/images/motion/`)
— каталог, снятый ими для Wix-сайта, а не сток. Вырезка делалась моделью
удаления фона; для боевой версии те же позиции лучше переснять на однородном
фоне.

Страница намеренно не на React: её задача — уехать клиенту одним файлом.

```bash
node scripts/build-motion-artifact.mjs /tmp   # версии со встроенными картинками
```

Скрипт собирает две копии с изображениями внутри HTML: `motion-standalone.html`
(целый документ, можно отправить вложением) и `motion-fragment.html` (без
обёртки, для хостинга со своей).

## Как редактировать контент

Когда база подключена, контент правится через `/admin`. Модули в `content/`
остаются исходным наполнением: из них база заполняется при первом запуске, и
на них сайт откатывается, если база недоступна или не настроена — сайт
собирается и работает без Supabase вообще.

Весь исходный контент — обычные TypeScript-файлы в `content/`. Тексты хранятся
объектами `{ en, ru, uz }`; если перевода нет, автоматически берётся
английский.

Добавить товар — дописать объект в `content/products.ts`:

```ts
{
  slug: "dried-apricot",           // адрес: /en/catalog/dried-apricot
  category: "dried-fruits",
  name: { en: "Dried Apricot", ru: "Курага", uz: "O‘rik qoqi" },
  description: { en: "…", ru: "…", uz: "…" },
  specs: [{ label: { en: "Moisture", ru: "Влажность", uz: "Namligi" },
            value: { en: "18% max.", ru: "18% макс.", uz: "18% maks." } }],
  image: "/images/products/dried-apricot.jpg",
}
```

Страница товара, карточка в каталоге, фильтр, поиск, sitemap и JSON-LD
подхватят его сами. То же с новостями в `content/news.ts`.

Строки интерфейса (кнопки, подписи, заголовки секций) — в
`content/dictionaries/`. Английский словарь задаёт тип: если в `ru.ts` или
`uz.ts` забыть ключ, сборка упадёт с ошибкой типизации, а не покажет пустое
место на сайте.

### Другая CMS

Все страницы читают контент через `lib/content/source.ts`. Чтобы перевести
сайт на Payload, Strapi или Sanity, переписывается только этот файл —
компоненты и страницы не меняются.

## Заявки с сайта

`POST /api/lead` принимает форму, валидирует, отсеивает ботов (honeypot) и
отправляет заявку:

- **в Telegram** — задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`;
- **в Bitrix24** — задайте `BITRIX_WEBHOOK_URL` (входящий вебхук с правом
  `crm.lead.add`), лид создаётся автоматически.

Можно включить оба канала одновременно. Если ни один не настроен, в
разработке заявка пишется в консоль, а в продакшене запрос возвращает ошибку —
чтобы заявки не терялись молча.

## Деплой

Проект разворачивается на Vercel без настройки: подключить репозиторий,
задать переменные окружения из `.env.example` — и всё. Бесплатного тарифа
хватает с запасом: все публичные страницы статические, динамически
выполняются только приём заявок и сама админка.

Свой сервер:

```bash
npm ci && npm run build && npm start   # слушает PORT, по умолчанию 3000
```

Готовый комплект для nginx + systemd — в [deploy/](deploy/README.md): конфиг
виртуального хоста, юнит службы, скрипт обновления и пошаговая инструкция.
Использовался для демонстрационной площадки на поддомене.

### Демонстрационная площадка

`/present` — витрина прототипа: одна страница со ссылками на сайт, обе
концепции, страницу анимации и админку, плюс честная сводка о том, какие
данные подтверждены, а какие проставлены отраслевыми. Закрыта от индексации.

Переменная `SHOWCASE_ROOT=true` заставляет корень открывать витрину вместо
языкового редиректа — так демонстрационный поддомен и боевой сайт собираются
из одного и того же кода.

## SEO

- Все страницы предрендерятся статически, включая карточки товаров и статьи.
- `sitemap.xml` c hreflang-альтернативами для трёх языков, `robots.txt`.
- Canonical и Open Graph на каждой странице, `x-default` на английскую версию.
- JSON-LD: `Organization` на всех страницах, `Product` в карточке товара,
  `NewsArticle` в статье.
- Заголовки, alt-атрибуты, семантическая разметка, навигация по хлебным крошкам.

## Доступность

Пропуск к содержимому с клавиатуры, видимый фокус, ARIA-атрибуты в шапке,
фильтрах и формах, контрастность текста по AA, полное уважение к
`prefers-reduced-motion` — при включённой настройке анимации отключаются.

## Что нужно получить от клиента

Всё, чего нет в открытом доступе на их текущем сайте, в код не выдумывалось.
Построчная сверка «что взято из источника, а что проставлено типовым» —
в [docs/content-sources.md](docs/content-sources.md). Перед запуском нужно
запросить:

1. **Телефоны и юридический адрес** — на сайте не опубликованы, сейчас в
   контактах только email и «Ташкент, Узбекистан».
2. **Точный адрес офиса** для карты (сейчас карта показывает город).
3. **Фотографии сотрудников** — в карточках команды пока инициалы.
4. **Сканы сертификатов** (FSSC 22000, SMETA, Halal, органика) — их номера и
   даты нигде не публиковались.
5. **Адреса и названия 4 производственных площадок** — компания указывает их
   количество, но не расположение.
6. **Полный список 55 стран экспорта** — сейчас показаны направления,
   подтверждённые их же новостями.
7. **Расхождение в цифрах**: на английской версии сайта мощность по
   сухофруктам указана как 15 000 тонн, на русской — 50 000 тонн. В коде
   стоит 15 000 (сумма по линиям сходится с заявленными 50 000 тонн в год).
   Нужно подтвердить.
8. **Фирменные материалы**: логотип в векторе, брендбук, если есть.
   Текущий логотип на сайте — растровый, в макете нарисован свой знак.

Технические характеристики товаров (упаковка, MOQ, сроки хранения, коды ТН
ВЭД) проставлены типовыми для отрасли — их нужно сверить со спецификациями
компании.
